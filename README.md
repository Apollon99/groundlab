# GroundLab

GroundLab is a reproducible benchmark that asks one question: **does more sophisticated
retrieval produce measurable gains, and are those gains worth the extra latency and compute?**
It compares BM25, dense retrieval, hybrid reciprocal rank fusion (RRF) and hybrid retrieval with
cross-encoder reranking on the same frozen data, split and metrics.

## Main result

Held-out SciFact evidence view: 188 evidence-bearing claims, frozen before scoring
([full report](docs/RESULTS.md)).

| Method | nDCG@10 | p50 latency |
|---|---:|---:|
| BM25 | 0.8370 | 0.36 ms |
| Dense | 0.8638 | 6.76 ms |
| Hybrid RRF | 0.8717 | 8.12 ms |
| Hybrid + rerank | 0.8749 | 122.08 ms |

**Reranking did not pay for its cost here.** Over hybrid RRF, reranking changed nDCG@10 by an
observed +0.0031 (95% cluster-bootstrap CI [-0.0284, +0.0338], Holm p = 1) while taking about
15× the p50 latency (122.08 ms vs 8.12 ms). None of the three pre-registered paired contrasts
(dense − BM25, hybrid − dense, rerank − hybrid) reached significance after Holm adjustment.
Latencies were measured on one machine (RTX 4080 Laptop GPU) as warmed, single-query retrieval
with one observation per query, so they describe that hardware and workload only.

In the exploratory views, hybrid RRF had the highest nDCG@10 on SciFact with BEIR qrels
(0.7280 vs 0.7007 with reranking) and on NFCorpus (0.3640 vs 0.3587). These views were not part
of the confirmatory test.

**Downstream claim verification (M7).** A separate, descriptive study used a pinned local
generator (Qwen2.5-1.5B-Instruct Q4_K_M on CPU) to evaluate 60 balanced SciFact claims under
four conditions: closed book with no abstracts, the top three abstracts from BM25, the top three
abstracts from reranked retrieval, and an oracle with up to three annotated evidence abstracts.
Moving from BM25 to reranked context raised grounded accuracy from
30.0% to 35.0% (18/60 → 21/60) and lowered stance accuracy from 61.7% to 56.7% (37/60 → 34/60).
These counts are descriptive, cover only this 60-claim sample, and are separate from the
retrieval inference above. See the [M7 report](docs/M7_RESULTS.md) and
[protocol](experiments/m7/PROTOCOL.md).

Aggregate numbers are also in [`results/`](results/README.md) as small CSV files.

## What is compared

| Arm | Description |
|---|---|
| Sparse | BM25 (BM25S, Lucene variant, k1=1.2, b=0.75) |
| Dense | `BAAI/bge-small-en-v1.5` (pinned), CUDA FP32, exact dot product |
| Hybrid | Reciprocal rank fusion (k=60) of sparse + dense top-100 |
| Hybrid + rerank | `cross-encoder/ms-marco-MiniLM-L6-v2` over the hybrid top-30 |

**Primary dataset:** SciFact evidence view (Ai2 dev = BEIR test, 188 evidence-bearing claims,
209 relevant pairs). **Secondary (exploratory):** SciFact with BEIR qrels (300 queries) and
NFCorpus (323 queries). See [docs/PROJECT_SPEC.md](docs/PROJECT_SPEC.md) and the frozen
[docs/EXPERIMENT_PLAN.md](docs/EXPERIMENT_PLAN.md).

## What this public snapshot contains

This repository is a sanitized public snapshot that starts with a single clean commit. It
includes the code, configs, frozen protocols and checksums (`freeze/`, `experiments/m7/`),
`uv.lock`, tests on synthetic fixtures, the aggregate reports
([docs/RESULTS.md](docs/RESULTS.md), [docs/M7_RESULTS.md](docs/M7_RESULTS.md)) and the aggregate
CSVs in [`results/`](results/README.md).

It does **not** include datasets, model weights, local reports, manifests or runs
(`data/`, `artifacts/`, `outputs/`), or per-query records. The full-reproduction commands below
therefore recreate the retrieval workflow locally by downloading the data and models from their
published sources at pinned hashes; they cannot be run from the snapshot alone. The quick
verification needs none of these. Replaying the original M7 artifacts is a separate matter with
stricter requirements, described in "Reproduce the M7 report" below.

Commit hashes printed in the reports, in this README and in [docs/HANDOFF.md](docs/HANDOFF.md)
(such as `825704a`) are identifiers from the original local experiment history. They are kept as
provenance references and cannot be browsed in this repository.

## Quick verification (CPU, about a minute after setup)

No dataset, model download or GPU is needed. The tests use small synthetic fixtures only.
Tests marked `cuda` or `pinned_models` skip on machines without a CUDA GPU or without the pinned
model files; pytest lists every skip with its reason, and a passing run without the models or a
GPU does not cover those paths. Run the setup step of the full reproduction first to enable the
model-dependent tests. Commands are PowerShell from the
repository root. `uv sync --locked` installs the exact `uv.lock` environment, which includes the
CUDA 12.8 PyTorch wheel even for CPU-only checks.

```powershell
uv sync --locked
.\.venv\Scripts\python.exe -m pytest                     # 219 tests; 6 skip without model files
.\.venv\Scripts\python.exe -m pytest experiments\m7      # M7 runner unit tests
.\.venv\Scripts\groundlab.exe simulate --out outputs\m4\simulation.json
```

These commands were checked in a fresh clone of this public repository on the same Windows
machine as the study (CUDA GPU present, pinned model files absent): 213 passed and 6 `pinned_models` tests skipped, the M7
tests passed, and `simulate` reproduced the original output byte for byte. They have not been
checked on another OS or on a machine without a GPU.

`simulate` reruns the pre-freeze synthetic stress test of the paired statistical method
(size, power at +0.02 and asymmetric cases) with a fixed seed. `.\scripts\test.ps1` runs pytest
plus `ruff check`, `ruff format --check` and `mypy --strict`.

## Full reproduction

### Requirements

- **Verified platform:** Windows 11 x64 (native, no WSL2), uv 0.12.7, CPython 3.11.16,
  PyTorch 2.11.0+cu128, NVIDIA RTX 4080 Laptop GPU (12 GB), driver 616.64. The CUDA path was
  verified on Windows only. Linux x64 is a supported platform target and the lock file resolves
  for it, but the CUDA stages and the held-out study were not run there.
- [uv](https://docs.astral.sh/uv/) 0.12 or newer (installs CPython 3.11 for you).
- For the dense, hybrid and rerank arms: an NVIDIA GPU with a CUDA 12.8-capable driver. BM25,
  fusion, metrics and statistics run on CPU. GPU stages never fall back to CPU silently; they
  exit with code 5.
- Network access once, to download the pinned data and models below.

### Pinned inputs

Every file is downloaded from its original source and checked against a SHA-256 in the code
before use. Nothing here is committed to the repository.

| Input | Source and pin | Defined in |

| SciFact (Ai2 release) | `data.tar.gz`, SHA-256 `11c62128…76be` | `src/groundlab/data/specs.py` |
| NFCorpus (BEIR) | `nfcorpus.zip`, SHA-256 `efe5be03…1b0b` | `src/groundlab/data/specs.py` |
| Dense encoder | `BAAI/bge-small-en-v1.5` at revision `5c38ec7c…` | `src/groundlab/models.py` |
| Reranker | `cross-encoder/ms-marco-MiniLM-L6-v2` at revision `233902d2…` | `src/groundlab/models.py` |
| Python dependencies | exact versions and hashes | `uv.lock` |

### Steps

```powershell
# 1. Environment: uv sync --locked, environment record, pinned model download + SHA-256 check
.\scripts\setup.ps1 -RequireCuda

# 2. Data: download, verify pinned SHA-256, build the three views, audit counts
.\.venv\Scripts\groundlab.exe data prepare --dataset scifact --data-dir data
.\.venv\Scripts\groundlab.exe data prepare --dataset nfcorpus --data-dir data

# 3. Optional dev-split smoke run of all twelve configs (build, run, evaluate)
.\scripts\dev_smoke.ps1

# 4. Held-out study: build missing indexes, run and evaluate all twelve frozen experiments
#    on the test split, then write the report to outputs\report\
.\scripts\held_out.ps1

# 5. Regenerate the report offline from the saved runs of step 4 (no retrieval, no GPU)
.\.venv\Scripts\groundlab.exe report
```

### How the freeze works

The test split is guarded. `groundlab run` and `evaluate` refuse the test split (exit code 4)
unless `freeze/<experiment>.json` is committed and still matches the current checkout. Each
manifest binds:

- the git tree hash of `src/groundlab`,
- the effective config hash, including parent configs,
- the SHA-256 of `uv.lock`,
- the SHA-256 of the prepared-data manifest,
- the SHA-256 of the frozen protocol `docs/EXPERIMENT_PLAN.md`.

The guard also rejects uncommitted changes under `src/`, `configs/`, `freeze/`, `uv.lock` and
the protocol. The twelve committed manifests were written by `groundlab freeze` before any
held-out scoring and still match this checkout, so `held_out.ps1` reruns the same frozen study.
Changing any bound input means a new study: run `groundlab freeze --data-dir data` and commit the
new manifests before touching the test split.

### What to expect on another machine

BM25, fusion, exact dense search and the metrics use deterministic tie-breaking. Dense
embeddings and reranker scores come from CUDA kernels, so rankings on a different GPU, driver or
library build may differ slightly and are not claimed to be bit-identical. Latency and GPU
memory describe the recorded machine only, and a fresh run records its own timings and
provenance, so its report bytes will differ from the archived ones. `groundlab report` on the
original saved local runs (not in this snapshot) reproduces `docs/RESULTS.md` and the CSVs in
`results/` byte for byte.

## Reproduce the M7 report

The public M7 aggregate report, [docs/M7_RESULTS.md](docs/M7_RESULTS.md), can be read directly.

M7 reads saved M6 outputs, so an exact rerun or replay depends on the original local M6 files.
These files are not published in this repository (they contain per-query rankings and the
original timings), so an exact M7 rerun is only possible on a machine that holds them. Rerunning
M6 from a fresh checkout can produce different rankings, timing and provenance bytes, so it will
not necessarily satisfy the frozen hashes, and the runner rejects any mismatch.
`experiments/m7/freeze.json` binds these files by SHA-256:

| Original M6 file | SHA-256 |
|---|---|
| `outputs/runs/bm25_scifact_evidence/test/run.trec` | `6dfe29f9c915af8a8fc820602c1c39a979c226d06c0ec65427247596909cea4b` |
| `outputs/runs/rerank_scifact_evidence/test/run.trec` | `593d04a05b55ee8691d309fdeceb4073ec892261d8a576be0d84a864a1426d0c` |
| `outputs/report/study.json` | `be759472dfc66a8fe96d1554d08658632b8ac7803c553bae124e909b3bf750a0` |

The freeze also binds the prepared-data manifest, `uv.lock`, the runner, the protocol, the
prompt, the 60-claim sample and every llama.cpp executable and DLL.

The command below regenerates the M7 report. It is meant for users who hold the saved local M7
trials and manifest in `outputs/m7/` (not included in this snapshot):

```powershell
.\.venv\Scripts\python.exe experiments\m7\runner.py report
```

To rerun or resume the frozen inference, use `runner.py run` with the original M6 artifacts
above, the pinned model file and the verified extracted llama.cpp runtime.
`experiments/m7/pins.json` records the exact source versions and hashes. The model is available
at its pinned Hugging Face revision. Extract the matching llama.cpp b12308 Windows CPU archive to
its pinned runtime directory after checking the archive SHA-256. The runner verifies the
executable, DLLs, dataset, prompt and retrieval artifacts before processing any trial.

## Command reference

All commands are PowerShell, run from the repository root.

```powershell
# Re-verify models or data without network access or writes
.\.venv\Scripts\groundlab.exe models fetch --model bge-small-en-v1.5 --verify-only
.\.venv\Scripts\groundlab.exe models fetch --model ms-marco-MiniLM-L6-v2 --verify-only
.\.venv\Scripts\groundlab.exe data prepare --dataset scifact --data-dir data --verify-only

# One experiment on the dev split (BM25 index on CPU; dense embedding cache on CUDA)
.\.venv\Scripts\groundlab.exe build --config configs\bm25_scifact_evidence.toml
.\.venv\Scripts\groundlab.exe run --config configs\bm25_scifact_evidence.toml --split dev
.\.venv\Scripts\groundlab.exe evaluate --config configs\bm25_scifact_evidence.toml --split dev

# Hybrid and rerank reuse the BM25 and dense indexes, so build both parents first.
# `build` of a hybrid/rerank config builds nothing: it verifies the parent indexes
# (and the reranker files). Parent indexes are read from artifacts\indexes (--index-root).
.\.venv\Scripts\groundlab.exe build --config configs\dense_scifact_evidence.toml
.\.venv\Scripts\groundlab.exe build --config configs\rerank_scifact_evidence.toml
.\.venv\Scripts\groundlab.exe run --config configs\rerank_scifact_evidence.toml --split dev
.\.venv\Scripts\groundlab.exe evaluate --config configs\rerank_scifact_evidence.toml --split dev
#    Configs: {bm25,dense,hybrid,rerank}_{scifact_evidence,scifact_beir,nfcorpus}.toml.
#    Outputs: outputs\runs\<name>\<split>\.

# Environment record
.\.venv\Scripts\groundlab.exe env check --out outputs\env_check.json
```

Hybrid and rerank design in short (details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md),
D-027 to D-030): RRF with k=60 over up to 100 real hits per parent, exact arithmetic, ties by doc
ID; the cross-encoder scores only the first 30 fused candidates and reorders only them. The
rerank run file carries rank-derived scores (strictly descending); evaluation reads the rank
column. Limits: the reranker sees at most 512 tokens per pair (long abstracts are truncated),
latency is one timing per query on one occasion.

Exit codes: `0` ok, `1` error, `2` usage/config error, `3` verification failed (hash,
count or metric cross-check), `4` refused (test split without a freeze), `5` CUDA required
but unavailable.

## Windows note: non-ASCII repository paths

Python 3.11 decodes `.pth` files with the locale codec, so a standard editable install
silently fails to import when the repository path contains non-ASCII characters (for example
a Windows folder name with accented letters). The project therefore uses hatchling's `dev-mode-exact`
editable mode, which needs the `editables` dev dependency (D-007). Always install with
`uv sync --locked` (dev dependencies included); `uv sync --no-dev` would break imports.
